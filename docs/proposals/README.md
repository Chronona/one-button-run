# 企画書

このディレクトリは、**まだ実装されていないゲームモードの企画書**を置く場所です。

週次の大型アップデート（`.github/workflows/weekly-update.yml`）は、既定ではエージェントが
自分でジャンルを選びます。ここに未実装の企画書があるときは、**発明する代わりにその企画書を
実装する**という運用にしています。経緯は [ADR 0006](../adr/0006-proposals-as-weekly-input.md)、
エージェントが読む実行指示は
[ADR 0002 の「週次エージェントへの実行指示」](../adr/0002-core-modes-split.md#週次エージェントへの実行指示)
にあります。

## 書式

各企画書は先頭に次の表を持ちます。

| 項目 | 意味 |
| --- | --- |
| `mode_id` | 実装先が `modes/<mode_id>/` になる短い英小文字の識別子 |
| `priority` | 実装順。小さいほど先。未実装のうち最小のものが次の実装対象 |

**実装状況を企画書に書き込む運用にはしていません。** `modes/<mode_id>/` が存在するか
どうかだけで判定します。ディレクトリは実装すれば必ずできるので、更新を忘れても
状態がずれません。

## 企画書本体と「このリポジトリで実装する際の制約」

企画書本体は更地からの開発を前提に書かれており、そのままでは L0 契約と衝突する箇所が
あります。各ファイルの末尾に「**このリポジトリで実装する際の制約**」という節を設けて、
衝突点と回避策を書いています。

**企画書本体は書き換えません。** 元の判断の記録として残し、このリポジトリ固有の事情は
すべてその節に追記します。実装する者は両方を読む必要があります。

企画とこのリポジトリの契約が衝突し、回避策も見つからない場合は、**契約を曲げてはいけません**。
企画のその要素を落とし、落としたことを PR の説明に書いてください。
