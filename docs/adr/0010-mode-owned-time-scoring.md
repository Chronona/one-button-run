# 0010. 時間によるスコア加算をモードが選ぶ: チャージ投擲は標的破壊だけで加点する

## Status

proposed（2026-10-02）。[ADR 0009](0009-score-bonus-hook.md) の決定 4 を置き換える。

> このリポジトリの現時点の判断を記録したものです。一般的な best practice の主張ではありません。

## Context

ADR 0009 でモードから加点できるようになったが、ホストは全モードに対して経過時間のスコア加算
（`score += delta`）を続けていた。チャージ投擲モードでは、標的を撃たずに待つだけでもスコアが増える。
このモードの目的は標的を壊すことで、時間はリソース（残弾と見送り）の消費としてすでに表現されている。
時間をスコアにすると、遊びの成果とスコアが対応しない。

## Decision

1. `core/game_mode.gd` に `scores_by_time() -> bool` を足す。既定は `true`。
2. ホストは `scores_by_time()` が `true` のモードに対してだけ、経過時間をスコアに加算する。
   `false` のモードでは、`add_score()` がスコアの唯一の入口になる。
3. チャージ投擲モードは `false` を返し、標的を1つ破壊するごとに `TARGET_SCORE`（100 点）を加点する。
4. ランナー、フラッピー、グラップルは既定のままで、スコアの定義は変わらない。

### 今回やらないこと

- 投擲数やステージ数に応じた加点の傾斜（ADR 0008 で見送った「少ない投擲数ほど高得点」）。
  フックと時間加算の切り離しが先に必要だったので、加点ルールの設計は別の変更で扱う。
- 加点時の演出（スコアのポップアップなど）。

## Consequences

- チャージ投擲のスコアは「破壊した標的数 × 100」になる。放置しても、構えずに見送り続けても増えない。
- 過去に記録されたハイスコア（`user://high_score.txt`）は、経過秒数が基準だった。チャージ投擲有効時に
  残っていると、標的 1 つ（100 点）では超えにくい。ハイスコアはモードごとに分けていないため、
  この点は未解決。必要になったらモードごとの保存先を別の ADR で決める。
- ADR 0009 の「`tests/golden/` の難易度カーブには影響しない」は引き続き成り立つ。難易度は
  スコアではなくモードの `get_difficulty()` から取っている。

## Confirmation

- `tests/contract/test_score_bonus.gd` が、有効なモードの `scores_by_time()` の宣言どおりに
  経過時間がスコアへ反映される（または反映されない）ことを検査する（CI が落とす）。
- `tests/contract/test_charge_score.gd` が、チャージ投擲で時間経過ではスコアが増えず、標的の破壊で
  `TARGET_SCORE` が入ることを検査する（CI が落とす）。
- 100 点という配点の釣り合いと、実プレイでの体感は CI では見ていない。
